How it behaves (same for every option)

The UI is small because the behaviour is automatic. These are the rules the design depends on.

Starts by itself.

Pressing Read aloud in a book starts preparing the next chapters. Opening a book you were listening to tops up the window. No Prepare buttons.

Never stops reading.

If the next chapter isn't ready yet, the live voice reads it as today and the prepared audio takes over at the next sentence once it exists.

Played audio deletes itself.

When you finish a chapter and move on, its audio is deleted. Skipping ahead also drops chapters you jumped over. Finishing a book, or not opening it for 7 days, clears all of its audio.

Speed doesn't throw work away.

Audio is made at 1× and sped up while playing, so 1.25× ↔ 2× is instant. Changing the voice re-prepares only what's ahead.

Highlight still follows.

Each file stores where every sentence starts, so the green highlight, tap-a-sentence and Back 10 s work exactly as now.

Android: background, battery-aware.

WorkManager job, offline voice only, pauses when the battery is low. No notifications unless Android requires one for a long job.

Web caveat to accept up front: a browser can't work in the background, so on web and the Mac app audio is prepared only while Feeder is open. Kokoro on the CPU is slower than real time, so the window grows only with the graphics card on (the default) or while you're reading, not listening.
